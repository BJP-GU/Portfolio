Reflections

I am incredibly proud of our work thus far. In particular, I value the rigorous design process we followed: beginning with a basic concept map to define the problem space, collaboratively developing a conceptual model of the solution (which remains a constant point of reference), and finally, realizing the efficacy of prototyping and designing directly in code.

In retrospect, I wish we had focused more effort upfront on validating the accuracy of the simulated user behaviors. While foundational research like Park et al.'s "Generative Agents: Interactive Simulacra of Human Behavior" confirmed that such simulations were possible, refining our system into a usable product has required significant, ongoing backend changes to the agent architecture.

Challenge & Background

Challenge

To enable users to effortlessly add contextual information to AI agent prompts for more accurate, relevant results in Onlook's Design-IDE AI Chat interface.

Background

While working at Onlook, I relied heavily on Notion, Cursor, and Slack. I became so accustomed to using the '@' feature to link context in those tools that I instinctively tried to use it while building prototypes in Onlook. This friction sparked a hypothesis: if I have this muscle memory, our users likely do too.

Without this capability, users were forced to manually describe or copy-paste code files and design assets. This broke their creative flow and often resulted in vague prompts and inaccurate AI outputs.

The opportunity was clear: create a familiar referencing system that empowers users to provide precise context effortlessly, optimizing both human usability and the AI agent's performance.

Problem Discovery & Validation

Validating the Problem

  • Conducted extensive product testing to understand the current state friction of adding context to prompts
  • Interviewed and observed users to understand the most commonly referenced contextual items and their process for adding them
  • Surveyed Onlook's Discord community to understand current state pain points related to adding context to AI Chats

Current State Experience Example

Key Findings

  • Primary Context Needs: Users most frequently need to reference code components (e.g., headers) and brand styles (colors, fonts).
  • Workflow Friction: Manual retrieval forces users to switch contexts, breaking the flow required for rapid, iterative prototyping.
  • Expanded Scope: Users explicitly requested the ability to reference entire pages, not just the current view.
  • Recency Matters: To speed up multi-turn prompting, users need quick access to their most recently used context.

Solution Exploration

Design Principles

To translate the key findings into a solution, I established two core principles:

  • Leverage Familiar Patterns: Minimize the learning curve by adopting the interaction models users already rely on in tools like Cursor, Notion, and Slack.
  • Abstract the Complexity: Create a simple interface for humans while ensuring the AI receives the deep, structured context it needs to perform accurately.

Challenge & Problem Discovery

Challenge

Increase new user retention, conversion to paid subscribers, and grow active user base for Onlook, an AI design tool startup competing in a crowded market with tools like Lovable, Figma, and others.

Problem Discovery

In-session analytics (PostHog) revealed critical drop-off points where users abandoned their sessions before completing key actions in Onlook's product, indicating missed opportunities to demonstrate Onlook's unique value over competitors, and failing to convert users to paid subscribers.

Drop-off Insights:

  • Users abandon sessions before initial site generation is completed due to lack of loading state feedback.
  • Limited awareness of Onlook's core features—code panel, design panel, brand styles, and infinite canvas—reducing engagement with differentiated product offerings.

Research & Ideation

Research Objectives

  • Why do users struggle to discover and adopt Onlook's current features?
  • Which features are most important for driving growth?
  • What are the "core" features which all users should know about?

Findings

  • Onlook does not onboard new users either hands-on or with a virtual walkthrough.
  • Onlook has complex and numerous feature offerings.
  • Engagement with "Site Publishing" and "Custom Domain Hosting" features leads to user conversion and retention.
  • Onlook's Core Features: AI Chat, Design Panel (Brand Styles), Code Window, Design-Preview Toggle, Site Publishing & Custom Domain Hosting.
